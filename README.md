# StellaVita (refined build)

**Offline health checks for astronauts, linked to the five hazards of spaceflight.** Team OrbitNsukka, NASA Space Apps Challenge 2026.

> **AI-generated project (D-44).** The code, data and documents in this repository were generated by an AI assistant (Claude, Anthropic) at the team leader's direction. How it was used, and what people have and have not reviewed, is in [`docs/AI_USE.md`](docs/AI_USE.md).

> **Guidance only — not a diagnosis.** Red reading, symptom or worry? Contact the flight surgeon.

## What it is

StellaVita is a progressive web app. An astronaut enters six readings by hand: heart rate, blood pressure, blood sugar, body temperature, sleep hours and mood. For each one the app shows:

- a **status** as a colour, a word and a symbol (Normal, Caution, Emergency), with the **reason** and the **source IDs** behind it;
- the approved **guidance** text for that indicator;
- a **"Why this is watched"** panel: how NASA's risk diagrams link the five hazards of spaceflight to what the reading watches (D-57). The panel explains. It never changes a status, and it never says which hazard caused a reading.

Every range, rule and reason is read from one threshold file, and every hazard link from one hazard file. None of their numbers, ratings or health wording is typed into the code.

- **Works offline** after one load. Everything stays on the device: no accounts, no analytics, no outside fonts or scripts.
- **Synthetic data only:** four fictional astronauts (SYN-A to SYN-D) over 30 days.
- **No NASA branding.** NASA is cited as a source only and does not endorse this project.

## Use it

**Hosted address:** `https://orbitnsukka.github.io/StellaVita_refined/app/`

This is the address the app has once GitHub Pages serves this repository from its root (D-59). **It was not tested in the build.** If the page does not open, Pages has not been turned on yet; run the app locally instead.

**Run it locally** (Python 3 is enough; nothing needs installing):

```bash
python -m http.server 8000
```

Then open `http://localhost:8000/app/`. A service worker needs `https` or `localhost`, so open it through the server, not as a file.

**A short walk-through:**

1. Read the limits statement and press **I have read this**.
2. On **Astronaut and data**, choose SYN-B and press **Load sample data**.
3. On **Today**, look at the six results. Open **Guidance** and **Why this is watched** under any of them.
4. On **History**, find 2026-10-28: sleep is Emergency, because it is the third short night in a row.
5. On **Enter a reading**, enter a reading of your own.
6. Switch the network off and reload. The app still works.
7. **Reset** (on Astronaut and data) wipes every reading and reloads the clean sample.

## Check it

```bash
python reference/check.py
```

```bash
python reference/tools/expected_colours.py --verify
```

```bash
npm install
```

```bash
npm test
```

`npm test` needs Node.js 20 or later. `npm install` is needed only for two checks: the browser test (Playwright) and the check that the committed CSS matches a fresh Tailwind build. Without it, those two are skipped and say so; every other test still runs.

What passes, what does not, and what was not tested: [`docs/BUILD_REPORT.md`](docs/BUILD_REPORT.md).

## Change it

The app runs as committed. After changing anything in `app/` or `src/`:

```bash
npm run build
```

This compiles the Tailwind CSS (`src/input.css` to `app/css/app.css`) and re-stamps the service worker, so devices fetch the new version. `npm test` fails if either step is forgotten.

**Never edit the fixed inputs:** `app/data/`, `reference/`, `tests/expected_colours.csv` and its `.meta.json`. A threshold or a rating changes only by a team decision and a new file version.
